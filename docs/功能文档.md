## 1. 产品概述

### 1.1 一句话定位

**SuperPet = 桌宠工坊 + 桌面 AI 助手。**

用户通过「上传照片或选形象 + 自选画风/动作/功能/语音」，一键生成专属桌宠；进阶用户通过订阅解锁**语音操控电脑**能力，让桌宠从「观赏宠物」升级为「能干活的桌面助手」。

### 1.2 两条产品主线

| 主线 | 形态 | 收费模式 | 核心价值 |
|---|---|---|---|
| A. 桌宠工坊（基础版） | 一次性/按量生成 + 素材能力选购 | **按量收费**，选得越多越贵 | 个性化、可分享、低门槛 |
| B. 语音操控电脑（增值版） | 持续订阅的桌面 AI 助手 | **订阅制** | 用自然语言操作电脑，提效 |

主线 A 是获客与付费转化入口，主线 B 是 LTV（用户生命周期价值）核心。

### 1.3 核心设计原则

1. **能力可插拔**：形象、画风、动作、功能、语音都是「能力包（Capability Pack）」，由配置驱动，新增能力不改主干代码。
2. **生成与运行分离**：工坊只负责「生产桌宠资产」，运行时只负责「消费资产」，两者通过标准化的桌宠包（Pet Pack）解耦。
3. **危险操作可控**：任何有副作用的指令都必须经过「风险分级 → 二次确认 → 可追溯」，默认最小权限。
4. **可离线降级**：语音、生成等云能力不可用时，桌宠本体与本地动作仍可用。

## 2. 目标用户与典型场景

### 2.1 用户画像

| 用户类型 | 特征 | 主要诉求 |
|---|---|---|
| 尝鲜型 | 学生、泛二次元用户 | 把自拍/宠物照变成会动的桌宠，图一乐 |
| 创作型 | 主播、画师、内容创作者 | 独特形象、定制动作、用于直播/视频 |
| 效率型 | 开发者、办公族 | 语音整理文件、开应用、控音量，减少鼠标操作 |
| 企业/团队（远期） | 需要统一桌面助手的团队 | 统一形象 + 统一技能库 + 权限管控 |

### 2.2 典型场景

- **场景 1｜一键生成**：上传一张猫的照片 → 选「像素风」→ 选「待机/走路/睡觉」3 个动作 → 选「文字对话」→ 生成，桌面上出现一只会走路的像素猫。
- **场景 2｜加量付费**：用户想再加「带语音的对话」和「番茄钟提醒」，生成价格随之上涨，界面实时显示价格明细。
- **场景 3｜语音助手**：订阅用户说「帮我把下载文件夹里的图片按月份整理一下」，桌宠复述计划 → 用户确认 → 执行 → 报告结果，并提供撤销。
- **场景 4｜高风险拦截**：用户说「删掉桌面所有文件」，桌宠判定为高风险 → 弹出二次确认 + 明确影响范围 → 用户拒绝则中止。

## 5. 模块一：桌宠工坊

### 5.1 流程总览

```
[1 选形象] → [2 选画风] → [3 选动作] → [4 选功能] → [5 语音配置] → [6 报价确认] → [7 生成] → [8 安装到桌面]
```

- 支持**任意步骤回退**，已选内容保留。
- 每一步实时更新右侧「价格明细」与「预计生成时长」。
- 支持「模板一键套用」（预设组合），降低决策成本。

### 5.2 步骤 1：形象来源

| 方式 | 说明 | 计费 |
|---|---|---|
| 上传照片 | 支持 JPG/PNG/HEIC，自动抠图、去背景、人脸/宠物识别 | 基础价 |
| 预设形象库 | 官方提供的角色底图，按分类浏览 | 基础价 / 部分 IP 形象加价 |
| 文字生成形象 | 输入描述词，文生图生成底图 | 按生成次数计费 |
| 手绘上传（多帧） | 高级用户上传序列帧 | 加价（省去动作生成） |

**约束与校验**
- 图片清晰度、尺寸、人脸占比校验，不达标时给出明确提示。
- 上传即触发**内容安全审核**（涉政/涉黄/暴力/侵权），不通过则拒绝并说明原因。
- 肖像权提示：用户须确认拥有上传图片的使用权。

### 5.3 步骤 2：画风选择

画风以**风格包（Style Pack）**形式提供，配置驱动，可后台新增：

| 分类 | 示例 |
|---|---|
| 像素 | 8-bit / 16-bit 像素风 |
| 卡通 | Q 版、日系赛璐璐、美式厚涂 |
| 写实 | 高清写实、黏土质感 |
| 艺术 | 水墨、油画、剪纸、蒸汽朋克 |
| 自定义 | 上传参考图风格迁移（高级，加价） |

**要点**
- 每个风格包包含：prompt 模板、后处理参数、是否支持动作生成、可用动作集。
- 风格与形象方式存在兼容矩阵（如「手绘序列帧」不能再套写实风格），UI 需动态禁用不兼容项。

### 5.4 步骤 3：动作选择

| 动作类别 | 示例 | 说明 |
|---|---|---|
| 待机 | 呼吸、眨眼、摇摆 | 默认必选，免费 |
| 移动 | 走路、跑动、跟随鼠标 | 按数量计费 |
| 情绪 | 开心、生气、委屈、惊讶 | 按数量计费 |
| 交互 | 被点击、被拖拽、被喂食 | 按数量计费 |
| 场景 | 睡觉、工作、打游戏 | 按数量计费 |
| 自定义 | 上传 GIF / 序列帧 / Live2D 模型 | 加价 |

**动作包（Action Pack）机制**
- 动作以标准化资产描述（帧序列 / 骨骼动画 / Live2D 参数），运行时按统一接口播放。
- 动作与「触发条件」绑定（时间、事件、对话关键词），支持后续在运行时里再配置。

### 5.5 步骤 4：功能选择

功能以**能力包**形式选购，可多选、可组合：

| 能力包 | 内容 | 计费 |
|---|---|---|
| 文字对话 | 接入 LLM，支持人设、记忆、语气 | 按量（含一定免费额度） |
| 语音对话（TTS） | 桌宠说话，可选音色 | 按量/月 |
| 语音输入（ASR） | 用户说话，桌宠听懂 | 按量/月 |
| 提醒助手 | 番茄钟、喝水、日程提醒 | 一次性 / 订阅 |
| 桌面感知 | 读取时间、电量、天气、当前应用 | 一次性 |
| 番茄工作法 / 专注模式 | 计时 + 桌宠联动动画 | 一次性 |
| 多桌宠 / 换肤 | 生成多个形象并切换 | 加价 |
| 云端同步 | 跨设备同步桌宠与配置 | 订阅 |

> 说明：「语音操控电脑」不作为工坊中的能力包售卖，而是独立订阅（见模块四）。

### 5.6 步骤 5：语音配置（当选择 TTS/ASR 时出现）

- 音色选择：预置音色库 + 声音克隆（高级，需授权声明）。
- 语速、音调、音量、口癖/语气词开关。
- 唤醒词自定义（默认「嗨，<桌宠名>」）。
- 语音权限说明与开关（麦克风权限、是否本地处理）。

### 5.7 步骤 6：实时报价

界面固定展示价格明细，做到**完全透明**：

```
基础生成费            ¥ 9.9
画风：像素风            ¥ 0.0
动作包：待机+走路+睡觉   ¥ 6.0
能力包：文字对话         ¥ 4.0
能力包：语音对话(TTS)    ¥ 5.0
────────────────────────────
合计                   ¥ 24.9   （可用点数抵扣 1200 点）
```

- 任何选项变化即时重算，价格变动有动画提示，避免「结账时才发现贵了」。
- 支持优惠券、首单折扣、点数抵扣、订阅会员折扣。

### 5.8 步骤 7：生成与产出

- 生成过程展示进度（形象 → 动作 → 打包），失败可重试且**不重复扣费**。
- 产出物：**桌宠包（Pet Pack）**，结构示例：

```
petpack/
  manifest.json        # 元信息、版本、能力清单、许可证
  appearance/          # 形象资源（多分辨率）
  animations/          # 动作资源 + 触发配置
  persona/             # 人设、语气、提示词
  capabilities.json    # 已购能力与额度
  preview.gif          # 分享预览
```

- `manifest.json` 定义统一契约，保证第三方形象/动作/技能可接入（可扩展性关键）。
- 支持导出/分享：生成分享卡片或预览 GIF；可选发布到形象市场（远期）。

### 5.9 步骤 8：安装到桌面

- 一键安装到桌面运行时，自动置顶、穿透点击可选、多显示器支持。
- 提供「重新编辑」入口：修改已生成桌宠的部分配置，按差额计费。

## 6. 模块二：桌宠运行时

### 6.1 渲染与动画
- 透明窗口、置顶/非置顶切换、窗口穿透模式、多屏与 DPI 适配。
- 动画状态机：待机 ↔ 移动 ↔ 情绪 ↔ 交互，支持优先级抢占（如「被点击」打断「待机」）。
- 性能目标：常驻内存与 CPU 占用可控，空闲时可降帧。

### 6.2 交互
- 鼠标：点击、双击、拖拽（含抛掷物理效果）、右键菜单。
- 托盘/菜单栏入口：显示/隐藏、设置、切换桌宠、退出。
- 触摸与手写笔（平板/触屏设备）。

### 6.3 对话
- 文字气泡对话，支持人设、上下文记忆、敏感内容过滤。
- 语音对话：唤醒 → ASR → LLM → TTS 全链路，支持打断（barge-in）。
- 对话记录本地可查，可一键清除；明确标注「云端处理 / 本地处理」。

### 6.4 提醒与挂机行为
- 定时提醒、番茄钟、日程联动。
- 挂机行为：随机走动、睡觉、跟随鼠标、跨屏漫游（可开关）。

### 6.5 设置
- 外观：缩放、透明度、置顶、穿透。
- 行为：动作触发频率、是否跟随、是否随机说话。
- 语音：唤醒词、音色、音量、麦克风设备。
- 隐私：数据本地/云端开关、日志清除、权限管理。

## 7. 模块三：计费与账户

### 7.1 计费模型

| 模式 | 适用 | 计量 | 说明 |
|---|---|---|---|
| 按量（点数） | 工坊生成、AI 调用 | 点数 Credit | 生成时按所选能力一次性扣点；对话/TTS 按调用量扣点 |
| 订阅 | 语音操控助手、云端同步 | 月/年 | 含额度，超额可降级或加购 |
| 加购包 | 点数包、额度包 | 一次性 | 促销与挽留手段 |

### 7.2 计价引擎（可配置）

- 所有价格项来自后台配置的**价格表（Price Book）**，支持：分项定价、组合折扣、区域定价、灰度调价。
- 计价结果必须可复算、可追溯：每笔订单保存「计价快照」（选了什么、单价、折扣、最终价）。
- 严禁硬编码价格到客户端；客户端只做展示与预估，最终以服务端计价为准。

### 7.3 订阅权益

| 权益 | 免费 | 基础订阅 | 高级订阅 |
|---|---|---|---|
| 语音操控电脑 | ✗ | 有限次数 | 不限次（公平使用） |
| 对话/TTS 额度 | 少量 | 中 | 高 |
| 高级技能（批量文件、多步任务） | ✗ | 部分 | 全部 |
| 云端同步 | ✗ | ✓ | ✓ |
| 优先生成队列 | ✗ | ✗ | ✓ |

> 具体档位与价格为运营配置项，本文只定义结构。

### 7.4 账户与订单
- 账号体系、设备绑定（限制同时在线设备数）。
- 订单、退款、发票、自动续费管理与到期提醒。
- 点数流水明细，支持导出。

## 8. 模块四：语音操控电脑（订阅增值）

### 8.1 价值主张
从「观赏宠物」升级为「桌面 AI 助手」：说一句话，它理解并执行。

### 8.2 全链路

```
唤醒/热键 → 录音 → ASR 转写 → 意图理解(LLM + 技能路由)
   → 参数抽取 → 风险分级 → [低]直接执行 / [中高]二次确认
   → 执行 → 结果播报 + 日志 → 可撤销
```

### 8.3 指令能力（技能库，可插拔）

技能以声明式定义注册，包含：名称、自然语言描述、参数 schema、所需权限、风险等级、是否可撤销。

| 技能域 | 示例指令 | 风险等级 |
|---|---|---|
| 应用控制 | 打开/切换/关闭应用 | 低 |
| 系统控制 | 调音量、亮度、静音、锁屏、截图 | 低 |
| 文件管理 | 整理文件夹、按类型归类、批量重命名、查找文件 | 中 |
| 信息查询 | 查天气、查日程、查剪贴板、总结当前文档 | 低 |
| 网络操作 | 搜索、打开网址 | 低 |
| 通讯 | 发消息、发邮件 | 高 |
| 删除/覆盖 | 删除文件、清空回收站、覆盖保存 | 高 |
| 系统设置变更 | 改电源计划、改默认应用、安装卸载 | 高 |
| 支付/交易类 | （默认不支持，可配置禁用） | 极高 |

### 8.4 风险分级与二次确认

| 等级 | 定义 | 处理策略 |
|---|---|---|
| 低 | 可逆、无数据损失 | 直接执行，事后提示 |
| 中 | 可逆但影响面较大 | 复述计划 + 单次确认 |
| 高 | 不可逆或有数据损失/对外发送 | 明确列出影响范围 + 二次确认（必要时要求输入确认词） |
| 极高 | 支付、权限授予、系统关键项 | 默认禁止，仅可在白名单配置下开启 |

**确认交互要求**
- 桌宠用自然语言复述「将要做什么、影响哪些对象、能否撤销」。
- 展示受影响对象的**具体清单**（如「将移动 128 个文件，其中 3 个为 .psd」）。
- 提供「执行 / 取消 / 先预览（dry-run）」三个选项。
- 支持**执行前快照/回收站**，便于撤销。

### 8.5 权限与安全
- 最小权限：默认只申请必要权限，敏感权限按技能粒度授权，可随时回收。
- 技能白名单/黑名单：用户可禁用整类技能（如禁用「删除」）。
- 目录沙箱：默认只允许操作指定目录（如下载、桌面、文档）。
- 全量审计日志：指令原文、解析结果、执行动作、时间、结果，本地保存、可导出。
- 敏感信息处理：不在日志中记录密码等敏感字段；语音是否上传云端需明示并可关闭。

### 8.6 可撤销与失败处理
- 可撤销技能需登记「撤销操作」（如文件移动可反向移动）。
- 执行失败要给出原因与建议，不静默失败。
- 多步任务（如「整理并压缩」）按步骤展示进度，可中途终止。

## 10. 技术架构建议（可扩展优先）

### 10.1 分层

| 层 | 职责 | 建议 |
|---|---|---|
| 桌面客户端 | 渲染、交互、本地执行、权限管理 | Tauri / Electron（透明窗口 + 系统 API 调用） |
| 技能执行层 | 技能注册、路由、执行、沙箱、撤销 | 插件化，声明式注册，本地进程内执行 |
| AI 服务层 | ASR / LLM / TTS / 图像生成 | 统一网关，模型可替换（多供应商适配） |
| 业务服务层 | 账户、计价、订单、订阅、权益 | 服务端为准，价格与能力全部配置化 |
| 数据层 | 用户、订单、桌宠包、日志 | 资产对象存储 + 元数据 DB |

### 10.2 关键扩展点

1. **Provider 抽象**：ASR/LLM/TTS/图像生成均通过统一接口，支持切换与灰度（避免绑定单一供应商）。
2. **能力包注册表**：新增能力只需新增一份配置 + 资源，不改主流程。
3. **技能协议**：新增技能只需实现标准接口（schema + 执行 + 风险声明 + 撤销）。
4. **Pet Pack 契约**：版本化 manifest，保证向后兼容。
5. **价格与权益配置化**：运营可自行调整，无需发版。

### 10.3 核心数据模型（示意）

```
User(id, plan, credits, createdAt)
Pet(id, userId, name, manifest, status, createdAt)
PetPack(id, petId, assets[], capabilities[], license)
Capability(id, code, type, priceRule, config)
Order(id, userId, items[], priceSnapshot, status)
Subscription(id, userId, planId, period, status, autoRenew)
Skill(id, code, domain, paramsSchema, riskLevel, undoable, enabled)
ExecLog(id, userId, deviceId, utterance, parsedIntent, skillId, result, riskLevel, confirmedAt)
```

## 11. 非功能需求

| 类别 | 要求 |
|---|---|
| 性能 | 桌宠空闲 CPU 占用低，动画流畅；语音链路首字响应尽量快 |
| 隐私 | 明确数据流向；支持本地处理模式；可一键清除数据 |
| 安全 | 技能沙箱、最小权限、审计日志、危险操作拦截 |
| 合规 | 内容审核、肖像权/声音权授权声明、生成内容标识 |
| 可用性 | 云服务不可用时桌宠本体可用；生成失败不重复扣费 |
| 跨平台 | 目标平台见待确认项（Windows / macOS / Linux） |
| 可访问性 | 键盘操作、屏幕阅读器兼容（尽量） |

## 12. MVP 范围建议

**第一期（MVP）**
- 工坊：上传照片 / 预设形象 + 3~5 种画风 + 待机/移动/情绪动作 + 文字对话 + 实时报价 + 生成安装。
- 运行时：桌面渲染、基础交互、文字对话、设置。
- 计费：点数钱包、按量计价、订单。
- 语音操控：**不做**，或仅做 1~2 个低风险技能（调音量、打开应用）验证。

**第二期**
- TTS/ASR 语音对话、提醒助手。
- 语音操控订阅上线：应用控制、系统控制、文件管理 + 风险分级 + 审计日志。

**第三期**
- 声音克隆、多桌宠、云端同步。
- 形象/动作/技能市场与开发者 SDK。

## 13. 风险与待确认项

### 13.1 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 按量定价导致用户犹豫 | 转化率低 | 实时透明报价 + 模板套餐 + 免费试用额度 |
| 图像/动作生成质量不稳定 | 口碑差 | 生成前预览、失败不扣费、人工兜底 |
| 语音操控误执行 | 数据损失、信任崩塌 | 风险分级 + 二次确认 + 可撤销 + 审计 |
| 系统权限被滥用 | 安全事件 | 最小权限 + 沙箱 + 白名单 |
| 模型成本高于定价 | 亏损 | 成本监控、额度限制、供应商可替换 |
| 平台政策/合规 | 下架风险 | 内容审核、授权声明、生成标识 |

### 13.2 待确认项（需产品/业务决策）

1. **目标平台优先级**：Windows 优先还是 macOS 优先？是否要 Linux？
2. **技术栈偏好**：Tauri / Electron / 原生？是否有既定技术选型？
3. **生成方式**：图像与动作生成是自研模型、调用第三方 API，还是混合？
4. **语音操控的技能边界**：第一期支持哪些技能？哪些明确不做（如支付）？
5. **定价档位**：点数与人民币的换算、订阅档位与额度，是否已有商业方案？
6. **是否需要账号登录才能使用基础版**？是否支持纯本地离线生成？
7. **内容审核与合规要求**：面向国内还是海外市场？是否有备案/合规约束？
8. **桌宠包是否要支持第三方导入/导出**（决定扩展性投入时机）？
