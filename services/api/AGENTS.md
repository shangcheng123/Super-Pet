# AGENTS.md — services/api

> Go 服务端：账户、点数钱包、计价、订单、订阅、权益。
> 上层规则见仓库根 [AGENTS.md](../../AGENTS.md)。

---

## 1. 职责边界

**做**：账户体系、点数钱包与流水、计价引擎（`/v1/quote`）、订单与计价快照、订阅与权益校验。

**不做**：依赖客户端实现细节；接受客户端传来的金额。

## 2. 计费铁律（本项目最不能出错的地方，必须人工逐行审）

1. **金额一律 decimal，禁止 float32/float64**。用 `shopspring/decimal` 之类的库，禁止 `float64` 参与任何金额运算，包括中间变量。
2. **服务端是唯一结算方**。客户端传来的只有「选了什么」（items）与 `quoteId`，**绝不接受客户端传来的单价或总额**。
3. **`/v1/quote` 是纯计算**，不落单、不扣点、可随时调用。返回 `quoteId` 与 `expiresAt`。
4. **下单必须复算**：带 `quoteId` 调 `/v1/orders` 时，服务端按当前价格表**重新计算并比对**。不一致或 `quoteId` 已过期，返回明确错误码，让用户重新确认——**不得沿用旧价**。
5. **扣点必须幂等**：以 `idempotencyKey` 去重，重复请求返回同一结果，不得重复扣点。
6. **扣费与任务绑定，任务终态才结算**。生成失败必须原路退回点数，且**不重复扣费**。
7. **每笔订单必须落「计价快照」**：选了哪些项、当时单价、折扣、最终价、点数抵扣额。要求可复算、可追溯。
8. **价格表后台配置化**（Price Book），支持分项定价、组合折扣、区域定价、灰度调价。运营调价不需要发版。

## 3. 契约

- 契约定义在 `packages/pricing-sdk`，Go 侧结构体由 Schema **代码生成**，不要手写。
- 响应字段名、错误码必须与契约一致。改契约走三方 review。
- 金额字段在 JSON 里用**字符串**传输（避免前端 JS 浮点精度问题），由 SDK 负责解析与格式化。

## 4. 订阅与权益

- 权益校验放在**服务端**，客户端只缓存展示态，**不得以客户端状态作为放行依据**。
- 订阅到期、超额降级、公平使用（fair use）判定都在服务端。

## 5. 测试（强制）

- **报价用例表**：每种组合（画风/动作包/能力包/优惠券/点数抵扣/订阅折扣）一个用例，覆盖到边界。
- **快照测试**：防止价格回归——价格表未变时，任何报价结果的变动都应导致测试失败。
- **幂等测试**：并发重复下单只扣一次点。
- **失败退款测试**：任务失败后点数回到原值。
- 命令：`cd services/api && go test ./...`

## 6. 技术约定

- Go；Postgres + Redis + 对象存储。
- 计价与权益相关逻辑必须有单元测试，不接受「先合进去后面补测试」。
