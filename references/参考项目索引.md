## 一、桌宠运行时 / 渲染 / 插件架构

### 1. `openpets` — 最值得先读 ★★★★★
- **仓库**：OpenPetsHQ/openpets ｜ 1196★ ｜ TypeScript ｜ MIT ｜ 2026-09-15
- **是什么**：Local-first 桌面伴侣平台，带动画宠物、**插件 SDK** 与编码助手集成。
- **借鉴点**：和 SuperPet 的形态最接近。pnpm monorepo：`apps/desktop`（客户端）、`packages/*`（cli / client / mcp / install-pet / 各 agent 适配）、`plugins/{official,community}`（插件分层）。还有 `DESIGN.md` 设计系统手册。
- **对应文档**：§10.2 扩展点、§9 内容平台与 SDK、§6 运行时。
- **重点看**：插件注册与加载机制、插件与宿主的边界划分、DESIGN.md 的 UI 设计系统。

### 2. `PPet` — 中文 Electron 桌宠
- **仓库**：zenghongtu/PPet ｜ 2032★ ｜ TypeScript ｜ MIT ｜ 2024-06-18
- **是什么**：Mac/Win/Linux 三端 Electron 桌宠，Live2D。
- **借鉴点**：Electron 透明窗口 + 跨平台打包（electron-builder）、`configs/` 与 `paths.json` 的配置外置思路。
- **对应文档**：§6.1 渲染、§10.1 客户端选型、§10.2 配置化。

### 3. `pixi-live2d-display` — Live2D 渲染底座
- **仓库**：guansss/pixi-live2d-display ｜ 1505★ ｜ TypeScript ｜ MIT ｜ 2024-08-20
- **是什么**：PixiJS 插件，显示任意 Live2D 模型。
- **借鉴点**：如果做 Live2D 动作，这是现成的渲染层；也是「动作资产标准化」的现实参考。
- **对应文档**：§5.4 动作包、§6.1 动画状态机。

### 4. `Ark-Pets` — 动作/动画调度做得好
- **仓库**：isHarryh/Ark-Pets ｜ 1090★ ｜ Java ｜ **GPL-3.0** ｜ 2026-09-05
- **是什么**：明日方舟桌宠，Java 桌面应用。
- **借鉴点**：**动画行为树 / 状态切换**的实现（待机→移动→交互的优先级抢占），`core` 与 `desktop` 的分层。
- **对应文档**：§6.1 动画状态机、§5.4 动作触发条件。
- ⚠️ GPL-3.0，仅参考思路。

### 5. `DyberPet` — Python 桌宠框架
- **仓库**：ChaozhongLiu/DyberPet ｜ 975★ ｜ Python ｜ **GPL-3.0** ｜ 2026-08-15
- **是什么**：基于 PySide6 的桌宠框架，含 `res/` 资源组织与多语言（`langs.pro`）。
- **借鉴点**：轻量框架的整体结构、资源目录规范。
- **对应文档**：§5.8 桌宠包结构。
- ⚠️ GPL-3.0。

### 6. `live2d-widget` — 网页看板娘
- **仓库**：stevenjoezhang/live2d-widget ｜ 10958★ ｜ TypeScript ｜ **GPL-3.0** ｜ 2026-09-16
- **借鉴点**：低成本嵌入方案；如果 SuperPet 想做网页版预览/分享卡片可参考。
- **对应文档**：§5.8 分享与预览。
- ⚠️ GPL-3.0。

### 7. `my-neuro` — AI 桌面伴侣 + 语音对话
- **仓库**：morettt/my-neuro ｜ 1363★ ｜ JavaScript ｜ MIT ｜ 2026-09-13
- **是什么**：自建 AI 桌面伴侣，可自定义角色与**语音对话**。
- **借鉴点**：角色人设配置、语音对话链路（ASR+LLM+TTS）的工程组装方式，是「工坊能力包」的现成样本。
- **对应文档**：§5.5 能力包、§6.3 对话、§5.6 语音配置。

## 二、语音操控电脑（模块四，订阅增值的核心）

### 8. `UFO` — 微软官方 Windows GUI Agent ★★★★★
- **仓库**：microsoft/UFO ｜ 9738★ ｜ Python ｜ MIT ｜ 2026-09-15
- **是什么**：UFO³，微软的 Windows 桌面 Agent，用自然语言操作 Windows 应用。
- **借鉴点**：**最贴合「语音操控电脑」**。看它的 Hybrid GUI 解析 + 控件定位、多应用任务编排（`dataflow/`、`galaxy/`）、以及**执行前的确认/控制流**设计。
- **对应文档**：§8.2 全链路、§8.3 技能库、§8.4 风险分级与二次确认。
- 注意：Windows 专属，SuperPet 若先做 macOS 需另找系统调用方案。

### 9. `OmniParser` — 屏幕解析（纯视觉 GUI 理解）
- **仓库**：microsoft/OmniParser ｜ 25388★ ｜ Jupyter Notebook ｜ CC-BY-4.0 ｜ 2026-07-20
- **是什么**：把屏幕截图解析成可交互元素列表的纯视觉工具。
- **借鉴点**：**「桌宠能看见屏幕」**的能力来源。当没有无障碍树/控件 API 可用时，靠视觉定位元素。
- **对应文档**：§5.5 桌面感知、§8.3 技能执行。
- ⚠️ CC-BY-4.0：商用需保留署名。

### 10. `autoMate` — 中文 computer-use agent
- **仓库**：yuruotong1/autoMate ｜ 3960★ ｜ Python ｜ MIT ｜ 2026-08-25
- **是什么**：类 Manus 的本地自动化 Agent，含 OmniParser 集成。
- **借鉴点**：中文场景的**任务规划 + 分步执行 + 进度反馈**，以及「本地自动化」的产品化形态。
- **对应文档**：§8.6 多步任务、§8.5 权限与沙箱。

### 11. `open-interpreter` — 自然语言执行引擎
- **仓库**：openinterpreter/openinterpreter ｜ 68338★ ｜ Rust ｜ Apache-2.0 ｜ 2026-09-15
- **借鉴点**：**「自然语言 → 代码 → 执行」的安全边界设计**：代码预览、用户确认、沙箱执行、中断机制。这套「先给用户看要执行什么」的交互，正是 §8.4 二次确认的产品范式。
- **对应文档**：§8.4 二次确认、§8.5 安全。

### 12. `leon` — 开源个人助理（技能体系最佳参考）★★★★★
- **仓库**：leon-ai/leon ｜ 17515★ ｜ TypeScript ｜ MIT ｜ 2026-09-15
- **是什么**：开源个人助理，自带技能（skill）生态。
- **借鉴点**：**技能的定义与注册协议**、意图识别 → 技能路由、NLU 与实体抽取、多语言。它的「技能 = 声明式配置 + 执行器」正是文档里 `Skill(id, paramsSchema, riskLevel, undoable)` 的成熟落地。
- **对应文档**：§8.3 技能库、§10.2 技能协议、§9 技能市场。

### 15. `ComfyUI` — 生成流水线编排 ★★★★
- **仓库**：Comfy-Org/ComfyUI ｜ 133419★ ｜ Python ｜ **GPL-3.0** ｜ 2026-09-16

## 六、建议的阅读顺序

1. `openpets/DESIGN.md` + `plugins/` — 插件化桌宠平台怎么搭（整体架构）
2. `leon/core` — 技能声明与路由协议（模块四的地基）
3. `UFO/ufo` + `OmniParser` — 桌面操控与屏幕理解（模块四的执行）
4. `open-interpreter` — 执行前的确认与安全边界（模块四的风险控制）
5. `PPet/src` + `pixi-live2d-display` — 桌宠渲染与透明窗口（模块二）
6. `ComfyUI` — 生成流水线（模块一的生成后端）
